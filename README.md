# AI Client Responder

Сервис для менеджера продаж: читает переписку по сделке из CRM, находит факты в короткой базе знаний
и возвращает два блока — **вежливый ответ клиенту** и **внутреннюю подсказку по допродаже**
с учётом того, что менеджер уже сказал и предложил в диалоге.

Демо-компания — **O-complex**: «уже 10 лет мы создаём продукты для здоровья и бережного очищения
организма». База знаний (14 статей: товары, услуга нутрициолога, доставка, оплата, возврат, акции,
противопоказания) и 6 диалогов придуманы для демонстрации.

- LLM — локально через **Ollama** (по умолчанию `gemma3:4b`), бюджет 0 $.
- **Mock amoCRM** — переписка в формате, близком к amoCRM API v4; заменяется реальным API без
  правки бизнес-логики ([как](docs/ARCHITECTURE.md#замена-mock-amocrm-на-реальный-amocrm)).
- **PostgreSQL** — база знаний с полнотекстовым поиском и журнал всех анализов.
- **FastAPI** + статическая страница без сборки.

**Демо:** https://ai-client-responder.ozzy1986.com · архитектура, промпт и решения — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Запуск локально

Нужны Python 3.12+, [Ollama](https://ollama.com) и PostgreSQL.

```bash
ollama pull gemma3:4b
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt      # Linux/macOS: .venv/bin/pip
cp ../.env.example .env                                # и поправьте DATABASE_URL
.venv/Scripts/alembic upgrade head
.venv/Scripts/python -m app.seed
.venv/Scripts/uvicorn app.main:app --port 8102
```

Откройте http://127.0.0.1:8102.

У автора PostgreSQL живёт на VPS, поэтому на Windows всё это делает один скрипт — он поднимает
SSH-туннель к базе `acr_dev`, применяет миграции и запускает сервер:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev.ps1
```

## Демо онлайн

**https://ai-client-responder.ozzy1986.com**

Приложение и PostgreSQL работают на VPS (1 CPU, 3 ГБ RAM — модель туда не помещается), а модель —
на ноутбуке автора. Когда ноутбук включён, один SSH-туннель отдаёт серверу локальную Ollama,
и сайт генерирует ответы вживую:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/vps-tunnel.ps1
```

Когда модель выключена, сайт остаётся рабочим: для демо-сделок показывается последний настоящий
ответ модели из журнала `analyses` с пометкой «сохранённый ответ, модель сейчас выключена» и датой.
Для отредактированного диалога сохранённого ответа нет — страница так и пишет.

Защита публичного сайта:

- смотреть и запускать анализ может любой; изменять базу знаний (`POST/PUT/DELETE /api/kb`) — только
  с паролем (HTTP Basic Auth в Apache; пароль — в `deploy/.env`, вне git);
- модель одна, поэтому одновременно выполняется один анализ (остальным — `429`, «модель занята»),
  и не больше 30 анализов в час с одного IP.

Деплой (из Git Bash): `deploy/deploy.sh` — тесты, релиз в `releases/<метка>` со своим venv, дамп
базы, миграции, seed, переключение симлинка, установка Apache-vhost и сертификата, healthcheck и
автооткат. Подготовка сервера — `deploy/setup-server.sh` (идемпотентный, его вызывает деплой).

## Качество

- `pytest` — 27 тестов логики без Ollama и PostgreSQL (`FakeLLM`, база знаний в памяти):
  роли, разбор диалога, повтор при невалидном JSON, проверки цен, утечек, правил здоровья/жалоб.
- `python scripts/eval_scenarios.py [--model qwen3:4b] [--runs 3]` — прогон 6 сценариев на живой
  модели с проверкой ожиданий из `_demo.expect`; отчёт в `docs/eval/<модель>.md`.

### Выбор модели

На ноутбуке с GTX 1050 (4 ГБ) сравнивались две модели, которые уже были в Ollama. Прогон:
6 сценариев × 2, `temperature = 0.2`, одинаковый промпт, Ollama 0.35.

| Модель | Прошли проверки | Время ответа | Типичные ошибки |
|---|---|---|---|
| **gemma3:4b** | **10–11/12** | 22–45 с | сама посчитала сумму («4 платежа по 750 ₽»), сослалась на «пункт 10 нашей базы» — все такие случаи поймали проверки кодом |
| qwen3:4b | 7/12 | 12–26 с | не предлагает допродажу там, где она уместна (30004), опускает срок доставки |

Выбрана **gemma3:4b**: лучше держит роли, формат подсказки и правила. Полные ответы —
[docs/eval/gemma3_4b.md](docs/eval/gemma3_4b.md), [docs/eval/qwen3_4b.md](docs/eval/qwen3_4b.md).
Модель меняется переменной `LLM_MODEL`.

Как менялось качество gemma3:4b по ходу настройки: 4/6 → 2/12 (после первых правок промпта,
на большем числе прогонов) → 8/12 (пример ответа в промпте — few-shot) → 10–12/12
(правила «здоровье/жалоба» в коде, проверка «товар, о котором клиент не спрашивал»,
исправление ложных срабатываний проверок). Главные выводы:

- маленькая модель стабильно держит формат, только если в промпте есть **пример ответа**;
- правила, которые можно проверить кодом (темы здоровья, жалобы, выдуманные цены, утечка разметки),
  надёжнее **проверять кодом**, а не только просить в промпте;
- ошибки, которые остаются, видны менеджеру в `warnings` — он всегда видит, что перепроверить.

## API

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/analyze` | `{"lead_id": "30004"}` — анализ сделки из CRM; `{"messages": [...]}` — произвольный диалог; `new_client_message` — дописать реплику клиента |
| `GET` | `/api/leads`, `/api/leads/{id}` | сделки mock amoCRM, диалог и «сырой» JSON |
| `GET/POST/PUT/DELETE` | `/api/kb`, `/api/kb/{id}` | база знаний |
| `GET` | `/api/kb/search?q=…` | какие статьи попадут в промпт |
| `GET` | `/api/analyses` | журнал анализов |
| `GET` | `/api/leads/{id}/saved-analysis` | последний сохранённый ответ по сделке (когда модель выключена) |
| `GET` | `/api/status`, `/api/healthz` | доступна ли модель; жива ли база |

Ошибки: `401` — изменение базы знаний без пароля, `404` — нет сделки/статьи/сохранённого анализа,
`409` — последним писал менеджер (нечего отвечать) или slug занят, `429` — модель занята или лимит,
`422` — невалидный запрос, `503` — модель недоступна или не смогла вернуть корректный ответ.
Swagger — `/docs`.

## Ограничения

- Вход по паролю — только на изменение базы знаний; журнал анализов и сохранённые ответы видны всем.
- Модель 4B на GTX 1050 отвечает за 20–60 с. Первый запрос после запуска Ollama — 1–2 минуты: модель
  загружается в память и дальше остаётся там (`LLM_KEEP_ALIVE=-1`; `5m` — выгружать после 5 минут простоя).
- Правила «здоровье/жалоба» — по ключевым словам: надёжно для явных случаев, тонкие формулировки
  остаются на совести промпта.
